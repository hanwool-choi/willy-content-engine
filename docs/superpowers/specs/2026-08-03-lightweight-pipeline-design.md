# 경량화: 배치 분석과 무신사 중심 수집 — 설계

## 배경

파이프라인이 무거워졌다. 수집 12장에 비전 API를 12번 순차 호출해
5~10분이 걸리고, 무료 티어 분당 한도에 걸려 일부가 유실된다. 솔루션의
핵심은 "빠르게 수집 → AI 캐릭터 이미지 생성 → 텍스트 콘텐츠 → 업로드"
이므로, 수집~배정 구간을 몇 분 안에 끝나는 경량 구조로 바꾼다.

핵심 통찰: 무거움의 원인은 수집량이 아니라 **호출 횟수**다. Gemini는
한 요청에 이미지 여러 장을 받으므로, 전 수집분을 **호출 1번**으로
일괄 분석할 수 있다.

## 확정 사항 (사용자 결정)

- 무신사 스냅은 필수이며 비중을 높인다. 유니클로 룩북은 톤이 유사한
  게 많아 보조로만 쓴다.
- 수집 구성: **무신사 6 + 유니클로 M 2 + W 2 = 총 10장**. 무신사는
  남녀 혼재라 유니클로 각 2장이 성별 안전핀 역할을 한다.
- 적합 룩 부족 시(예: 여름 소나기 예보로 전원 우천 부적합):
  **차선 룩 조건부 추천**. 빈 칸 대신 사유("우천 부적합 — 기온은
  적합")를 달아 차선 룩을 채워두고, 컨펌 단계에서 사용자가 쓸지
  뺄지 결정한다. "억지 배정 금지" 원칙은 컨펌 게이트로 지켜진다.

## 변경 사항

### 1. 수집 구성

`looks_per_source` 단일값을 **소스별 수집량**으로 바꾼다:
musinsa_snap 6, uniqlo_men 2, uniqlo_women 2. 설정으로 조정 가능.
수집 소스 코드는 그대로, 수량 배분만 달라진다.

### 2. 배치 분석 (12콜 → 1콜)

분석기 인터페이스를 `analyze_batch(raw_looks, weather) -> list[LookAnalysis]`
로 바꾼다. 한 요청에 이미지 전부(순서 보존)와 내일 날씨(기온·강수확률)를
넣고, 룩 순서대로 JSON 배열을 받는다.

판정 필드 축소 — 7개에서 4개로:

| 유지 | 삭제 |
|---|---|
| gender, temp_range, rain_ok, style_tags | sleeve, outer, layers, fabric_weight, coverage |

`temp_range`는 아카이브 ±3℃ 폴백과 4주 재등장 금지의 기반이라
유지한다. 삭제 필드는 산출 문서 장식용이었다. `palette`도 삭제한다.

- 응답 배열 길이가 요청 이미지 수와 다르면 ValueError → 1회 재시도 →
  그래도 실패하면 gather 전체를 오류로 드러낸다 (부분 성공 없음.
  배치 1콜에서 per-look 허용 오차는 의미가 없다).
- 429/503/타임아웃 재시도 로직은 배치 호출에 그대로 적용된다.
- Claude 경로(`LookAnalyzer`)도 같은 배치 인터페이스로 맞춘다
  (Anthropic API도 다중 이미지 1콜 지원).
- `season` 파생 규칙(기온 기반, 결정론)은 유지.

### 3. 배정 단순화 (헝가리안 제거)

하루 4칸에 헝가리안은 과하다. scipy 의존성과 함께 제거하고:

1. 성별별 후보를 기존 비용 공식으로 정렬
   (`cost = |temp_repr − median(temp_range)| + 우천 999 + 범위밖 5`)
2. 비용 오름차순 상위 2장을 픽1·픽2로. 동점은 look_id 사전순
   (결정성 유지)
3. **적합 후보(비용 < 999)가 모자라면** 나머지 칸은 부적합 룩 중
   비용 최소를 "조건부 추천"으로 채우고 사유를 붙인다
4. 후보가 아예 없으면 아카이브 폴백 → 그래도 없으면 빈 칸 + 경고
   (기존과 동일)

같은 룩 중복 배정 금지, 아카이브 보충(min_pool)·재등장 금지는 유지.

### 4. UI

- 조건부 추천 슬롯은 경고 톤(황색)으로 사유를 표시한다
- 슬롯별 편집(교체·비우기)은 이번 범위 제외 — 컨펌/중단이 게이트다

### 5. 아카이브 하위호환

기존 `archive/looks.db`에는 삭제 필드 컬럼이 남아 있다. SQLite는
컬럼 삭제가 번거로우므로 **기존 컬럼은 남겨두고 새 코드가 읽고 쓰지
않는 방식**으로 호환한다. 새로 만드는 DB는 축소 스키마로 생성한다.

### 6. 산출 문서와 생성 프롬프트

- `아이템정보.docx`에서 삭제 필드 표기를 제거하고 성별·기온·스타일
  태그·우천 여부만 남긴다.
- 이미지 생성 프롬프트 빌더(`generator/base.py`)도 축소 필드 기준으로
  정리한다. 생성 시 원본 룩 사진이 레퍼런스로 함께 가므로 착장의
  세부 텍스트 묘사(소매·겹수·소재감·색상)에 기댈 필요가 없다 —
  성별·스타일 태그·날씨 컨텍스트만 남긴다.

## 유지되는 것

날씨 조회(KMA/Open-Meteo), 2단계 컨펌 흐름, 폴더·문서 산출 구조,
NoopGenerator, truststore 주입, 수집 중복 제거, 수집 버튼 잠금과
서버 gather 잠금.

## 기대 효과

- 비전 호출: 12회 → **1회** (분당 한도 문제 소멸)
- 소요 시간: 5~10분 → **1~2분** (수집 ~1분 + 분석 1콜 ~30초)
- 코드: scipy 제거, 판정 필드 5종 제거, 배정 로직 단순화
- 여름 우천일에도 빈손이 아니라 "조건부 추천 + 사용자 결정"

## 테스트 전략

- 배치 분석기: 페이크 HTTP로 다중 이미지 요청 구성·순서 보존·길이
  불일치 거부·날씨 컨텍스트 포함을 검증
- 배정: 정렬 픽 로직과 조건부 추천 분기, 동점 결정성 회귀 테스트
- 기존 헝가리안 테스트는 새 로직 계약으로 재작성
- 네트워크 없는 픽스처 원칙 유지
