# 콘텐츠 아이디어 보울 — 설계

## 배경

지금 솔루션은 `[내일 뭐입지?]` 한 종류의 콘텐츠만 만든다. 같은 채널에
올릴 두 번째 콘텐츠 축으로, 패션 신소식(신제품 발매, 협업 콜라보,
스트릿 브랜드 드랍, 아카이브 세일, 시즌오프 세일)을 매일 모아 보고
그중 고른 것을 채널 말투의 텍스트 콘텐츠로 바꾸는 기능을 붙인다.

기존 흐름과 나란히 놓기 위해 화면을 **탭**으로 나눈다:
`[내일 뭐입지?]` / `[콘텐츠 아이디어 보울]`.

## 확정 사항 (사용자 결정)

- **텍스트 연계**: 목록에서 항목을 **고르고 버튼을 누르면** 그 내용에
  맞는 텍스트가 생성되는 흐름
- **선별**: 필터로 걸러내지 않고 **전부 나열**한다. 대신 유저 반응
  (좋아요·댓글·조회)이 있는 항목에 **뱃지로 추천 표시**
- **소스**: 국내 사이트를 조사해 7곳으로 시작

## 소스 (7곳)

robots는 `urllib.robotparser` 표준 파서로 판정했고, 모든 소스에서 실제
제목을 뽑아 내용이 주제에 맞는지 확인한 뒤 골랐다.

| id | 소스 | 성격 | 수집 | 반응 지표 |
|---|---|---|---|---|
| `eomisae_os` | 어미새 패션할인 | 할인·세일 | httpx + 정규식 | 좋아요·댓글·조회 |
| `eyesmag` | 아이즈매거진 | 협업·드랍 | **Playwright** | 조회수 |
| `hypebeast` | 하입비스트 | 신상·콜라보 | RSS | 없음 |
| `esquire` | 에스콰이어 패션 | 남성 스타일링 | httpx | 없음 |
| `gq` | GQ 스타일 | 남성 아이템·스니커즈 | httpx | 없음 |
| `elle` | 엘르 패션 | 여성 스타일링 | httpx | 없음 |
| `vogue` | 보그 패션 | 트렌드 | httpx | 없음 |

- 아이즈매거진만 완전 클라이언트 렌더링이라 브라우저가 필요하다.
  서버 HTML에 글이 없고 초기 데이터에도 없다. 내부 API는 존재하지만
  경로가 공개돼 있지 않다. 룩 수집용 Playwright를 재사용한다.
- **제외**: 무신사 매거진·에펨코리아·딜바다는 robots.txt가 차단한다.
  에이블리·크림을 제외한 것과 같은 기준으로 넘지 않는다.
  마리끌레르는 셀럽 화보 비중이 커서 뺐다. 뽐뿌는 의류 카테고리
  주소를 찾지 못했고 기본 게시판은 전자제품이 대부분이라 보류.

소스 추가·제거는 `ideas/sources.py`의 목록 한 줄로 끝나야 한다.

## 데이터 모델

```python
@dataclass
class IdeaItem:
    source: str                      # 소스 id
    title: str
    url: str                         # 절대 URL
    published_at: datetime | None    # 상대시간만 주는 곳이 있어 옵션
    category: str | None             # "패션 > 슈즈", "sneakers" 등
    thumbnail_url: str | None
    views: int | None
    comments: int | None
    likes: int | None
    is_hot: bool = False             # 반응 뱃지 (수집 후 파생)
```

`published_at`이 없는 소스는 목록 순서를 최신순으로 신뢰한다.

## 반응 뱃지

소스마다 지표 스케일이 다르다(어미새 좋아요 3~10, 아이즈 조회 4천~1.7만).
공통 임계값은 의미가 없으므로 **소스별 임계값**을 설정에 둔다.

```python
HOT_THRESHOLDS = {
    "eomisae_os": {"likes": 5, "comments": 10},
    "eyesmag": {"views": 5000},
}
```

지표 중 하나라도 임계값을 넘으면 `is_hot=True`. 임계값이 정의되지 않은
소스는 항상 `False`이고 뱃지 대신 카테고리 라벨만 보여준다.

## 아키텍처

```
src/willy/ideas/
  models.py      # IdeaItem
  sources.py     # IdeaSource 정의 7개 (id, 이름, url, 수집방식, 파서)
  fetchers.py    # rss / html / browser 세 가지 수집 방식
  collector.py   # 오케스트레이션 — 소스별 상한, 부분 실패 허용
  detail.py      # 선택 항목의 상세 본문 (텍스트 생성용)
```

- 룩 수집기(`willy/collector/`)와 분리한다. 대상도 산출물도 다르다.
- 한 소스가 실패해도 나머지는 수집한다(룩 수집기와 같은 원칙).
- **소스당 최신 10건**까지. 7곳이면 하루 최대 70건으로, 전부 나열해도
  훑을 수 있는 양이다.
- 파서는 순수 함수로 둔다: `(html_or_xml: str) -> list[IdeaItem]`.
  네트워크와 분리해야 픽스처로 테스트할 수 있다.

## 텍스트 생성 연계

1. 사용자가 목록에서 항목을 고른다(복수 선택).
2. 선택 항목의 **상세 페이지를 그때 1회씩** 가져와 본문 일부를 뽑는다.
   제목만으로는 가격·브랜드·발매일이 빠져 텍스트가 빈약해진다.
   선택은 보통 1~3건이라 요청 수 부담이 없다.
3. `texter.py`에 `write_from_ideas(items_with_details)`를 추가한다.
   말투 예시(`STYLE_EXAMPLE`)와 3가지 톤 구조는 룩 텍스트와 공유하고,
   프롬프트 본문만 소식용으로 바꾼다.
4. 실패하면 기존과 같이 템플릿 폴백으로 초안 1종을 낸다.

## 화면

### 로컬 앱 (`run.py`)

상단에 탭 두 개. 탭 전환은 클라이언트에서만 처리한다(서버 라우팅 없음).

- **[내일 뭐입지?]** — 지금 화면 그대로
- **[콘텐츠 아이디어 보울]**
  - `[아이디어 불러오기]` 버튼 (룩 수집과 별개로 동작)
  - 소스 필터 칩 — 그룹은 소스 정의에 둔다:
    전체 / **할인**(어미새) / **드랍·신상**(아이즈, 하입비스트) /
    **매거진**(에스콰이어, GQ, 엘르, 보그)
  - 카드: 썸네일, 제목, 소스 배지, 카테고리, 시간, 🔥 반응 뱃지, 체크박스
  - `[선택 항목으로 텍스트 만들기]` → 3가지 톤 카드 + 복사 버튼

### 게시 페이지 (GitHub Pages)

정적이라 선택·생성이 불가능하다(브라우저에서 AI를 부르려면 키를
공개해야 한다). 같은 탭 구조를 쓰되 아이디어 탭은 **읽기 전용 목록**으로
둔다. 아침에 훑어보고 쓸 만한 게 있으면 로컬 앱에서 생성한다.

## 서버 API

| 엔드포인트 | 동작 |
|---|---|
| `POST /api/ideas` | 7개 소스 수집 → 목록 반환 |
| `POST /api/ideas/texts` | `{urls: [...]}` → 상세 수집 후 3가지 톤 |

`/api/ideas`도 수집 잠금을 건다. 여러 탭에서 눌러 중복 수집하는 것을
막는 이유는 룩 수집과 같다.

## 배치 연동

`build_site.py`가 룩 수집에 이어 아이디어도 수집해 게시 페이지에 싣는다.
RSS·HTML이 대부분이라 수십 초면 끝난다. 아이즈매거진 때문에 브라우저
세션을 짧게 한 번 더 연다(룩 수집 세션은 그때 이미 닫혀 있다).

아이디어 수집이 통째로 실패해도 보드 게시는 진행한다. 아이디어 섹션만
비우고 경고를 남긴다.

## 테스트

- 각 소스의 실제 응답 일부를 `tests/fixtures/ideas/`에 저장하고 파서를
  검증한다. **네트워크를 타지 않는다** (기존 원칙 유지).
- 파서별로: 정상 추출, 항목 0건, 구조 변경(필드 누락) 시 예외 대신 건너뛰기
- 반응 뱃지: 임계값 경계, 임계값 미정의 소스
- 상대 URL → 절대 URL 변환 (게시 페이지에서 깨진 링크를 이미 겪었다)
- 수집기: 한 소스 실패가 전체를 막지 않음, 소스당 상한
- 텍스트 생성: 프롬프트에 선택 항목이 들어가는지, 폴백
- 웹: 두 엔드포인트, 잠금, 이스케이프

## 범위 밖

- 아이디어 항목의 이미지 다운로드·AI 이미지 생성 (기존과 같이 수동)
- 자동 발행·예약 게시
- 아이디어 아카이브·중복 방지 (첫 버전은 매일 새로 수집만 한다.
  같은 소식이 며칠 반복되면 그때 붙인다)
