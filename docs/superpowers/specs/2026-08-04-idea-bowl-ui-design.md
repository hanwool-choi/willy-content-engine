# 게시 페이지 콘텐츠 아이디어 보울 UI 개선 설계

작성일: 2026-08-04

## 문제

게시 페이지(https://hanwool-choi.github.io/willy-content-engine/)의 아이디어
보울 섹션은 68건을 훑어보기 어렵다. 원인은 세 가지다.

1. **사진용 격자를 재사용했다.** `.pool`은
   `grid-template-columns:repeat(auto-fill,minmax(150px,1fr))`로 룩 썸네일을
   깔기 위한 격자다. 아이디어 카드에는 사진이 없어 150px 폭 텍스트 타일 68개가
   11px 글씨로 빽빽하게 깔린다.
2. **소스 라벨이 제목을 덮는다.** `.look .src`가 `position:absolute`로 사진 위에
   얹히도록 만들어졌는데, 사진이 없으니 텍스트 위에 떠 있다.
3. **정렬·묶음·개수 제한이 없다.** 수집 순서 그대로라 어미새 10건이 먼저
   몰리고, 반응 좋은 항목이 68건 중 어디 있는지 찾을 방법이 없다.

부수적으로, 게시 페이지에는 탭이 없어 로컬 앱(탭 2개)과 구조가 어긋난다.
사용자가 아이디어 보울을 탭으로 찾다가 못 찾은 일이 실제로 있었다.

## 목표

폰과 PC 양쪽에서 68건을 한눈에 훑고 쓸 만한 소재를 골라 원본으로 넘어갈 수
있게 한다.

## 결정 사항

| 항목 | 결정 |
|---|---|
| 사용 기기 | 폰·PC 양쪽 — 반응형 |
| 정리 기준 | 성격별 묶음(할인/드랍·신상/매거진) + 묶음 안 반응순 |
| 카드 형태 | 텍스트 중심, 한 줄에 한 건 (썸네일 미사용) |
| 배치 | 상단 탭 2개 |
| 표시량 | 묶음별 10건 + 더 보기 |
| 렌더링 위치 | 빌드 타임(파이썬). JS는 탭 전환과 더보기만 |

### 렌더링 위치를 빌드 타임으로 정한 이유

대안으로 JSON을 페이지에 심고 JS가 전부 렌더링하는 방식을 검토했으나 뺐다.
JS가 없으면 빈 화면이 되고, 고정 묶음·고정 정렬이라는 지금 요구에 과하며,
기존 `test_site.py`의 HTML 문자열 검증 방식에서 벗어난다.

`<details>` 접이식도 검토했다. 더보기까지 JS 없이 되지만 탭은 어차피 JS가
필요하고, 기본 접힘이면 "훑기 어렵다"는 원래 문제가 되돌아온다.

## 화면 구조

```
CHOI WILLY LAB · 옷장연구소
내일 뭐입지?                        ← h1 유지
┌─────────────┬──────────────────────┐
│ 내일의 보드 │ 콘텐츠 아이디어 보울 │   ← 탭
└─────────────┴──────────────────────┘
```

탭 라벨은 `내일의 보드`와 `콘텐츠 아이디어 보울`이다. `내일 뭐입지?`를 탭
라벨로 쓰면 h1과 같은 문구가 두 번 나온다.

- **보드 패널**: 날씨 티켓, 경고, 내일의 보드, 텍스트 콘텐츠, 수집된 룩
  (현재 내용과 순서 그대로)
- **아이디어 패널**: 아이디어 보울 전용

주소 해시 `#ideas`로 진입하면 아이디어 탭이 활성화된 상태로 열린다. 아이디어
부분만 링크로 공유할 수 있다.

아이디어가 0건이면 탭 막대 자체를 렌더하지 않고 보드 내용만 보인다. 탭이
하나뿐인 탭 UI는 뜻이 없다. 이때 `#ideas`로 들어와도 무시하고 보드를 보여준다.

## 아이디어 패널

묶음은 `할인 → 드랍·신상 → 매거진` 순으로 고정한다. `sources.py`의
`SOURCE_GROUPS` 선언 순서가 그대로 표시 순서다.

```
할인  12건
─────────────────────────────────────────────
드릭스 크랙 그래픽 오버핏 슬리브리스 9,900원
어미새 · 🔥 · ♥3 · 조회 948
─────────────────────────────────────────────
지오다노 메신저백 16,640원 외
어미새 · ♥1 · 조회 1,030
                              [ 더 보기 (2건) ]
```

- 행 전체가 `<a>`다. 폰에서 제목만 정확히 겨냥할 필요가 없다.
- 제목 15px, 메타 12px. 현재는 11px 한 종류라 위계가 없다.
- 전용 클래스 `.idea-list` / `.idea-row` / `.idea-title` / `.idea-meta`를 쓴다.
  `.pool`과 `.look`은 재사용하지 않는다 — 겹침의 원인이다.
- 메타 줄은 `소스 · 🔥 · ♥n · 조회 n · 카테고리` 중 값이 있는 것만 이어 붙인다.
- 빈 묶음은 제목째 렌더하지 않는다.
- 더 보기는 한 방향이다. 누르면 그 묶음이 전부 펼쳐지고 버튼은 사라진다.
  다시 접는 기능은 두지 않는다.

## 정렬 규칙

묶음 안에서 다음 우선순위로 정렬한다.

1. `is_hot`이 True인 것
2. 반응 지표를 가진 것. 그 안에서 대표 지표값 내림차순
3. `published_at` 최신순
4. 수집 순서 (안정 정렬로 보존)

**대표 지표**는 하나로 정한다: `likes`가 있으면 `likes`, 없으면 `views`,
그것도 없으면 `comments`. 항목마다 다른 지표를 섞어 비교하지 않기 위해서다
(어미새는 `likes`, 아이즈는 `views`로 결정된다).

`None`은 "모름"이며 0으로 취급하지 않는다. 지표가 아예 없는 항목은 2단계에서
뒤로 밀리고 3단계 기준으로 정렬된다.

### 스케일 충돌이 없는 이유

`hotness.py`의 `HOT_THRESHOLDS`는 `eomisae_os`와 `eyesmag` 두 소스에만 있다.
지표를 가진 소스가 묶음마다 최대 한 곳이다.

| 묶음 | 소스 | 지표 |
|---|---|---|
| 할인 | 어미새 | ♥·댓글·조회 |
| 드랍·신상 | 아이즈(조회), 하입비스트(없음) | 아이즈만 |
| 매거진 | 에스콰이어·엘르·GQ·보그 | 없음 |

따라서 어미새 `♥5`와 아이즈 `조회 5,000`을 한 줄에 세워 비교하는 상황이
발생하지 않는다. 매거진 묶음은 사실상 발행일 최신순이 된다.

## JS 없을 때의 동작

`<html>`에 스크립트가 `js` 클래스를 붙인다. 탭 숨김과 더보기 접힘은 그 클래스가
있을 때만 CSS로 작동한다.

- JS 정상: 탭이 갈리고 묶음당 10건 표시
- JS 차단·실패: 두 패널 모두 펼쳐지고 68건 전부 노출. 탭 막대와 더보기 버튼은
  숨긴다 (눌러도 반응 없는 버튼을 남기지 않는다)

`Ctrl+F` 검색, 링크 공유, OG 미리보기가 어떤 경우에도 깨지지 않는다.

## 모듈 경계

`src/willy/publisher/site.py`는 이미 432줄이다. 아이디어 렌더링을 새 파일로
분리한다.

**`src/willy/publisher/ideas_section.py`**

| 함수 | 입력 | 출력 | 책임 |
|---|---|---|---|
| `group_ideas(items)` | `list[IdeaItem]` | `list[tuple[str, str, list[IdeaItem]]]` | 묶음 키·라벨·정렬된 항목. 빈 묶음 제외 |
| `render_idea_panel(items)` | `list[IdeaItem]` | `str` (HTML) | 패널 전체 마크업 |

`site.py`는 `render_idea_panel`을 호출하고 CSS와 탭 골격만 담당한다.
`ideas_section.py`는 `sources.py`의 `SOURCE_GROUPS`·`IDEA_SOURCES`에만
의존하고 `PipelineState`는 모른다.

정렬 로직을 HTML 문자열 없이 직접 단위 테스트할 수 있게 되고, `site.py`가 더
부풀지 않는다.

## 테스트

### 신규 `tests/test_ideas_section.py`

- 묶음이 할인 → 드랍·신상 → 매거진 순으로 나온다
- 항목이 없는 묶음은 결과에 없다
- `is_hot` 항목이 같은 묶음의 비-hot 항목보다 앞에 온다
- 지표가 있는 항목이 없는 항목보다 앞에 오고, 수치 내림차순이다
- 대표 지표가 `likes` → `views` → `comments` 순으로 골라진다
  (`likes`와 `views`를 모두 가진 항목은 `likes`로 비교된다)
- 지표가 없으면 `published_at` 최신순이다
- `published_at`도 없으면 입력 순서가 유지된다
- 11건 이상이면 11번째부터 접힘 표시가 붙고 더보기 버튼에 잔여 건수가 찍힌다
- 10건 이하면 더보기 버튼이 없다
- 제목과 URL에 든 `<`, `"`, `&`가 이스케이프된다

### 기존 `tests/test_site.py` 갱신

- 탭 막대와 패널 두 개가 렌더된다
- 아이디어 섹션이 아이디어 패널 안에 있다
- 아이디어 0건이면 탭 막대가 없다
- 기존 28개 테스트는 수정 없이 통과해야 한다
