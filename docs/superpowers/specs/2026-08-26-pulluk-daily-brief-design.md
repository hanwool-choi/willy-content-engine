# 최펄럭 데일리 콘텐츠 브리핑 설계

작성일: 2026-08-26
상태: 설계 확정 (사용자 승인 대기)
관련 문서: `2026-08-07-pulluk-channel-design.md` (채널 컨셉·말투·즐겨찾기 소스)

매일 아침 9시, 그날 스레드([@choi.flap.guide](https://www.threads.com/@choi.flap.guide))에 올릴
콘텐츠 기획 초안을 카카오톡 나와의 채팅으로 받는다. PC가 꺼져 있어도 동작해야 한다.

## 1. 결정 요약

| 항목 | 결정 | 비고 |
|---|---|---|
| 전송 경로 | 카카오 공식 "나에게 보내기" REST API | PlayMCP 미채택 (§2) |
| 실행 | GitHub Actions cron (00:00 UTC = 09:00 KST) | PC 무관 |
| 소재 | 네이버 지도 즐겨찾기 3폴더 (카페·식당·스팟) | 기존 수집기 재사용 |
| 주제 선정 | 요일 로테이션 + 신호 보정(시즌·날씨) + 아카이브 중복 제거 | |
| 브리핑 구성 | 메인 기획 1건 + 맛집 1곳 집중분석 | |
| 팝업 | **브리핑에서 제외** | 코스 스튜디오 웹앱에는 유지 |
| 말투 | @choi.flap.guide 실게시물 기반 학습 | |

## 2. PlayMCP를 쓰지 않는 이유

[PlayMCP](https://tech.kakao.com/posts/734)의 '카카오톡 나챗방'은 이 용도로 가장 많이 쓰이는 MCP 서버가
맞지만, 공식적으로 **PC 전용**이고 대화형 AI 클라이언트에서 OAuth로 연결하는 구조다. 즉 PC가 꺼져
있으면 동작하지 않아 "PC off여도 전송" 요구와 양립하지 않는다.

나챗방 MCP도 결국 카카오 공식 [나에게 보내기 API](http://developers.kakao.com/docs/ko/kakaotalk-message/rest-api)의
래퍼이므로, 같은 API를 직접 호출하면 도착지(나와의 채팅)는 동일하면서 무인 실행이 가능하다.
나에게 보내기는 **앱 검수가 불필요**하고 `talk_message` 권한만 있으면 된다.

## 3. 아키텍처

```
09:00 KST · GitHub Actions (.github/workflows/pulluk-brief.yml)
  │
  ├─ ① 소재 수집   tools/pulluk_favorites.py (즐겨찾기 3폴더)
  │                 + 플레이스 보강 데이터(평점·리뷰·영업·주차) = assets/pulluk/data.js
  │                 + KMA 날씨 (기존 willy 엔진 연동 재사용)
  ├─ ② 주제 결정   요일 로테이션 → 신호 보정 → 아카이브 중복 제거 → 오늘의 기획 1건
  ├─ ③ 후보 선별   메인용 5~6곳 + 심층분석 1곳
  ├─ ④ 초안 생성   Gemini 1콜 (실패 시 템플릿 폴백)
  ├─ ⑤ 페이지 발행 gh-pages/brief/YYYY-MM-DD.html + brief/latest.html
  ├─ ⑥ 카톡 전송   나에게 보내기 3통 (요약 카드 + 전문 2분할)
  └─ ⑦ 아카이브    brief/archive.json 갱신 후 gh-pages 커밋
```

기존 자산 재사용: 즐겨찾기 수집기, 플레이스 보강(설명·주차), Gemini 텍스트 생성 패턴,
gh-pages 배포 구조. **신규 개발은 주제 선정 엔진 · 카톡 전송 · 브리핑 페이지 세 가지.**

## 4. 주제 선정 엔진

### 4.1 요일 로테이션

| 요일 | 기획 유형 | 설명 |
|---|---|---|
| 월·수·금 | 카테고리 족보 | 음식 카테고리 5~6곳 (칼국수·양꼬치·곰탕 등) |
| 화·목 | 지역 코스 | 방문명소 + 맛집 동선 (성수·올림픽공원 등) |
| 토 | 근교·드라이브 | 서울 밖 당일 왕복권 |
| 일 | 변주 | 해장·심야·혼밥·주차 되는 집 등 상황형 |

### 4.2 신호 보정 (그날만 로테이션 교체)

- **날씨**: 강수 확률이 높으면 실내 위주 코스로 전환 (KMA 단기예보)
- **시즌**: 월별 가중 키워드 (8월=냉면·막국수·콩국수, 12월=붕어빵·호빵 등)

### 4.3 중복 방지

`brief/archive.json`에 `{date, type, topic, places[]}` 누적.
- 같은 **주제**는 60일 내 재사용 금지
- 같은 **가게**는 30일 내 재등장 금지 (심층분석은 예외 — 족보에 나온 집을 심층으로 파는 건 허용)
- 후보가 고갈되면 규칙을 완화하며 재시도하고, 그래도 없으면 "소재 부족" 안내를 브리핑에 명시

## 5. 브리핑 구성

1. **메인 기획 1건** — 족보형이면 5~6곳 리스트(지역·평점·한줄평), 코스형이면 시간·동선 타임라인
2. **맛집 1곳 집중분석** — 대표메뉴·가격·평점/리뷰수·영업시간·브레이크타임·주차 안내문·근처 연계 장소
3. **게시 전 확인 목록** — 가격/휴무 등 변동 가능 항목 자동 표기

### 5.1 경험담 원칙 (중요)

채널의 힘은 "먹어본 사람의 말"에서 나온다. **AI는 경험담을 지어내지 않는다.**
- 데이터로 확인된 사실(평점·리뷰수·메뉴·가격·영업시간·주차 안내문)만 단정해서 쓴다
- 한줄평은 초안을 제시하되 `※확인` 표시를 붙여 사용자가 자기 문장으로 교체하게 한다

### 5.2 말투

`STYLE_EXAMPLES`에 실제 게시물 원문을 저장해 Gemini 프롬프트에 넣는다 (족발·만두·삼겹살·평양냉면·순대국 편).
고정 요소: `내 기준 [지역] [메뉴] 탑티어 족보 정리해봄.` / `*광고/협찬 아님` /
번호 + `상호(지역) : 한줄평` / `나만 아는 OO 성지 있으면 풀어주세요` /
`(+) 팔로우 해두면 맛집/카페/볼거리 매일 올라옴`

## 6. 카카오톡 메시지 설계

기본 템플릿 텍스트형은 **최대 200자**, 피드형은 제목+본문 4줄 제한. 초안은 300~400자이므로 3통으로 나눈다.

| 통 | 템플릿 | 내용 |
|---|---|---|
| 1 | feed | 제목(날짜+기획명) · 훅 요약 · 대표 이미지 · 버튼(전문 보기 → 브리핑 페이지) |
| 2 | text | 초안 전문 1/2 (200자 이내) |
| 3 | text | 초안 전문 2/2 + 심층분석 요약 |

- 이미지: 네이버 플레이스 대표 사진 URL을 시도하고, 없거나 실패하면 이미지 없이 전송
- 엔드포인트: `POST https://kapi.kakao.com/v2/api/talk/memo/default/send`

## 7. 브리핑 페이지

`gh-pages/brief/YYYY-MM-DD.html` (+ `latest.html`). 코스 스튜디오와 같은 디자인 토큰 사용.
- 초안 전문 + **복사 버튼** (카톡보다 붙여넣기 편함)
- 장소별 네이버지도 링크, 심층분석 카드, 게시 전 확인 목록
- 하단에 지난 브리핑 목록 (아카이브)
- 카톡 전송이 실패해도 페이지는 항상 남는다

## 8. 인증·토큰 운영

- Secrets: `KAKAO_REST_API_KEY`, `KAKAO_REFRESH_TOKEN`, `GH_PAT_SECRETS`(토큰 회전용), 기존 `GEMINI_API_KEY`·`KMA_SERVICE_KEY`
- 매 실행: refresh token → access token 발급. 응답에 새 refresh token이 오면(만료 1개월 이내 시 발급)
  `gh secret set KAKAO_REFRESH_TOKEN`으로 자동 갱신
- 실패 시: GitHub 이슈 생성(메일 알림) + 워크플로 실패 처리
- 토큰은 저장소에 절대 커밋하지 않는다 (기존 `.env` 규칙과 동일)

## 9. 파일 구조

```
tools/pulluk_brief.py        # 신규 — 주제 선정 + 초안 생성 진입점
tools/pulluk_kakao.py        # 신규 — 토큰 갱신 + 나에게 보내기 전송
tools/pulluk_brief_page.py   # 신규 — 브리핑 페이지 HTML 생성
tools/kakao_token_setup.py   # 신규 — 사용자 1회 실행용 토큰 발급 스크립트
.github/workflows/pulluk-brief.yml  # 신규 — 09:00 KST 크론
assets/pulluk/style_examples.json   # 신규 — 채널 실게시물 말투 예시
```

## 10. 사용자 1회 준비 절차

카카오 로그인이 필요하므로 사용자가 직접 수행한다 (자격증명은 Claude가 다루지 않는다).
1. developers.kakao.com 앱 생성 → REST API 키 확보
2. 카카오 로그인 활성화 + Redirect URI 등록 + `talk_message` 동의항목 설정
3. `python tools/kakao_token_setup.py` 실행 → 브라우저 인증 → refresh token 출력
4. GitHub Secrets에 등록

## 11. 실패 모드와 폴백

| 실패 지점 | 폴백 |
|---|---|
| 즐겨찾기 수집 실패 | 커밋된 `data.js` 스냅샷 사용 |
| Gemini 실패 | 템플릿 기반 초안(코스 스튜디오 `draftText` 로직) |
| 날씨 조회 실패 | 신호 보정 생략, 로테이션 그대로 |
| 이미지 URL 없음 | 이미지 없이 전송 |
| 카톡 전송 실패 | 브리핑 페이지는 발행 + GitHub 이슈로 알림 |
| 토큰 만료 | 이슈 알림 후 재발급 안내 |

## 12. 범위 밖 (v2 후보)

- 브리핑 카드 이미지 자동 생성(HTML→PNG)
- 스레드 자동 게시 (현재는 사람이 복사해 올린다)
- 반응 데이터 회수 후 주제 선정에 반영
- 댓글 제보를 다음 회차 소재로 자동 수집
